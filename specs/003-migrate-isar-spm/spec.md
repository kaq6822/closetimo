# Feature Specification: 로컬 데이터 엔진 장기 호환성

**Feature Branch**: `003-migrate-isar-spm`

**Created**: 2026-07-25

**Status**: Draft

**Input**: User description: "Isar 의존성의 Swift Package Manager 미지원 경고를 임시 비활성화가 아닌 장기 해결 방식으로 제거한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기존 옷장 데이터 보존 (Priority: P1)

기존 사용자는 앱을 업데이트한 뒤에도 등록한 의류, 착용 기록, 세탁 기록과 설정을 그대로 이용할 수 있다.

**Why this priority**: 로컬 데이터는 사용자가 직접 축적한 개인 기록이므로 빌드 체계 개선보다 데이터 보존이 우선한다.

**Independent Test**: 이전 버전에서 의류와 착용·세탁 기록 및 설정을 만든 뒤 업데이트하고, 모든 값과 관계가 동일하게 조회되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이전 버전에서 의류와 착용·세탁 기록을 저장한 사용자, **When** 새 버전으로 업데이트하여 앱을 실행하면, **Then** 기존 데이터가 누락이나 중복 없이 표시된다.
2. **Given** 이전 버전에서 알림 설정과 마지막 탭을 변경한 사용자, **When** 새 버전을 처음 실행하면, **Then** 해당 설정과 마지막 탭이 유지된다.
3. **Given** 데이터 이전 과정에서 복구할 수 없는 오류가 발생한 상황, **When** 앱이 저장소를 열려고 하면, **Then** 원본 데이터는 훼손되지 않고 진단 가능한 오류가 기록된다.

---

### User Story 2 - 기존 앱 기능의 동일한 동작 (Priority: P2)

사용자는 데이터 엔진 변경을 의식하지 않고 기존 옷장 관리 기능을 이전과 동일하게 사용할 수 있다.

**Why this priority**: 내부 의존성 교체가 사용자 흐름이나 오프라인 동작을 변경해서는 안 된다.

**Independent Test**: 빈 설치에서 의류 등록부터 착용 기록, 세탁 완료, 수정과 삭제까지 전체 흐름을 네트워크 없이 수행한다.

**Acceptance Scenarios**:

1. **Given** 빈 옷장, **When** 사진 유무에 관계없이 의류를 등록하면, **Then** 의류가 즉시 목록과 홈 통계에 반영된다.
2. **Given** 등록된 의류, **When** 착용 기록을 추가·수정·삭제하고 세탁을 완료하면, **Then** 카운터와 상태 및 히스토리가 기존 규칙대로 갱신된다.
3. **Given** 앱이 네트워크에 연결되지 않은 상태, **When** 등록·검색·착용·세탁 흐름을 수행하면, **Then** 모든 작업이 정상 완료된다.

---

### User Story 3 - 지속 가능한 Apple 플랫폼 빌드 (Priority: P3)

개발자는 임시 호환성 비활성화 없이 지원되는 의존성 관리 방식으로 iOS 앱을 빌드할 수 있다.

**Why this priority**: 현재 빌드는 가능하지만 미지원 경로는 향후 도구 버전에서 오류로 전환될 예정이므로 지속 가능한 빌드 기반이 필요하다.

**Independent Test**: 프로젝트 기본 설정에서 iOS 디버그 빌드를 실행하고 미지원 패키지 경고 없이 산출물이 생성되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 지원되는 안정 개발 환경, **When** iOS 디버그 빌드를 실행하면, **Then** 네이티브 의존성 관리 미지원 경고 없이 빌드가 성공한다.
2. **Given** 새 개발자가 저장소를 체크아웃한 환경, **When** 문서의 표준 부트스트랩 절차를 따르면, **Then** 사용자별 전역 우회 설정 없이 동일한 빌드 결과를 얻는다.
3. **Given** Android 빌드 환경, **When** 디버그 앱을 빌드하면, **Then** 기존 최소 지원 버전과 패키징 요건을 유지하며 성공한다.

### Edge Cases

- 이전 버전 데이터베이스 파일은 존재하지만 일부 이미지 파일이 삭제되었을 때 데이터 열기와 목록 표시는 계속 동작해야 한다.
- 데이터베이스가 비어 있거나 최초 설치인 경우 불필요한 이전 작업 없이 정상 초기화되어야 한다.
- 앱이 이전 도중 종료되더라도 다음 실행에서 원본을 보존한 채 안전하게 재시도할 수 있어야 한다.
- 동일한 저장소를 이미 이전한 뒤 다시 실행해도 데이터가 중복되거나 카운터가 변하지 않아야 한다.
- 지원되는 최소 iOS 및 Android 버전에서 네이티브 라이브러리를 불러올 수 있어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 기존 사용자의 의류, 착용 기록, 세탁 기록과 설정을 누락·중복 없이 보존해야 한다.
- **FR-002**: 시스템은 이전 작업 실패 시 기존 로컬 데이터 원본을 훼손하지 않아야 한다.
- **FR-003**: 시스템은 이전 작업을 여러 번 실행해도 동일한 결과를 내야 한다.
- **FR-004**: 시스템은 의류 등록·조회·검색·필터·정렬·수정·삭제 기능의 기존 동작을 유지해야 한다.
- **FR-005**: 시스템은 착용 기록 추가·메모 수정·기록 삭제·세탁 완료에 따른 파생 상태 계산을 유지해야 한다.
- **FR-006**: 시스템은 네트워크 연결 없이 모든 핵심 옷장 관리 흐름을 완료해야 한다.
- **FR-007**: iOS 빌드는 미지원 네이티브 의존성 관리 경고 없이 성공해야 한다.
- **FR-008**: Android 빌드는 기존 최소 지원 버전에서 성공해야 한다.
- **FR-009**: 프로젝트는 개발자 전역 설정이나 임시 비활성화 옵션에 의존하지 않아야 한다.
- **FR-010**: 이전 실패와 저장소 초기화 실패는 영문 런타임 로그로 원인을 진단할 수 있어야 한다.
- **FR-011**: 데이터 엔진과 생성 도구의 버전은 서로 호환되는 동일 계열로 고정되어야 한다.
- **FR-012**: 데이터 이전과 기존 기능 보존을 검증하는 자동화 테스트가 제공되어야 한다.

### Key Entities

- **의류**: 사용자가 등록한 옷과 사진 경로, 분류, 관리 방식, 착용·세탁 파생 상태를 포함한다.
- **착용·세탁 이벤트**: 의류에 연결된 시간순 기록으로 착용 메모와 세탁 완료 이력을 나타낸다.
- **환경설정**: 알림 선택, 최초 실행 시점과 마지막으로 선택한 탭 등 앱 사용 환경을 나타낸다.
- **이전 상태**: 기존 데이터의 발견 여부, 이전 완료 여부와 재시도 가능 여부를 나타낸다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 대표 기존 데이터 세트의 의류·이벤트·설정 100%가 업데이트 후 동일하게 조회된다.
- **SC-002**: 데이터 이전을 연속 두 번 실행해도 레코드 수와 모든 사용자 값이 변하지 않는다.
- **SC-003**: 등록부터 착용, 세탁, 수정과 삭제까지 전체 핵심 흐름이 오프라인에서 100% 성공한다.
- **SC-004**: iOS 및 Android 디버그 빌드가 모두 성공하며 iOS 출력에 미지원 네이티브 의존성 관리 경고가 0건이다.
- **SC-005**: 정적 분석 경고·오류가 0건이고 전체 자동화 테스트가 100% 통과한다.
- **SC-006**: 앱 업데이트 후 첫 저장소 초기화가 일반적인 모바일 사용 환경에서 3초 이내에 완료된다.

## Assumptions

- 현재 배포 전 단계이지만 기존 개발·테스트 데이터도 사용자 데이터와 동일한 보존 기준으로 다룬다.
- 서버 동기화나 외부 백업은 이 기능 범위에 포함하지 않는다.
- 화면 디자인과 사용자 입력 흐름은 변경하지 않는다.
- 기존 로컬 데이터 형식과 직접 호환되지 않는 경우에도 원본 보존과 재시도 가능한 명시적 이전 경로를 제공한다.
- 최소 지원 버전은 iOS 13 및 Android API 21을 유지한다.
