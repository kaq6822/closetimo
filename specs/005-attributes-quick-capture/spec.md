## User Scenarios & Testing *(mandatory)*

### User Story 1 — 타이핑 없이 옷 정보 붙이기 (Priority: P1)

사용자는 등록·수정 화면에서 세부 종류·색상·계절·용도를 **칩을 눌러** 고른다. 사진을 고르면 색상이 미리 선택되고,
이름을 비워 두면 `검정 니트`처럼 이름이 자동으로 붙는다. 이름에 `울 코트`를 입력하면 세부 종류·소재가 제안된다.

**Independent Test**: 사진 1장을 고르고 이름 없이 저장했을 때 색상이 채워지고 자동 이름이 붙는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 등록 화면, **When** 종류 `상의`를 고르면, **Then** 상의의 세부 종류 칩(티셔츠·셔츠·니트…)만 보인다.
2. **Given** 세부 종류 `니트`를 골랐고 계절을 고르지 않은 상태, **When** 저장하면, **Then** 계절은 비어 있다
   (자동 기본값은 칩으로 제안만 하고 사용자가 고른 값만 저장한다).
3. **Given** 사진을 고른 등록 화면, **When** 분석이 끝나면, **Then** 대표 색상(최대 3개)이 선택된 상태로 표시되고
   사용자가 바꿀 수 있다. 사용자가 이미 색상을 골랐으면 덮어쓰지 않는다.
4. **Given** 이름을 비우고 색상 `검정`, 세부 종류 `니트`, **When** 저장하면, **Then** 이름은 `검정 니트`다.
5. **Given** 이름 입력란에 `베이지 울 코트`, **When** 입력하면, **Then** 비어 있는 축(종류 아우터·세부 종류 코트·색상 베이지·소재 울)이
   제안으로 채워진다. 사용자가 이미 고른 축은 바꾸지 않는다.

### User Story 2 — 여러 장을 한 번에 넣고 카드로 정리 (Priority: P1)

사용자는 앨범에서 여러 장을 한 번에 골라 옷을 만들고, 카드가 한 장씩 넘어가는 **정리하기** 화면에서 탭만으로 분류한다.

**Acceptance Scenarios**:

1. **Given** 등록 화면, **When** `여러 장 한 번에`로 사진 5장을 고르면, **Then** 옷 5벌이 `미분류`로 만들어지고
   (사진·색상·자동 이름 포함) 정리하기 화면이 첫 옷으로 열린다.
2. **Given** 정리하기 카드, **When** 종류·세부 종류·색상·계절을 고르고 `다음`을 누르면, **Then** 저장되고 다음 옷이 보인다.
   이름이 자동 이름이었으면 새 속성으로 다시 만든다.
3. **Given** 정리하기 중간, **When** 화면을 나가면, **Then** 남은 옷은 미분류로 남고 홈 `정리 대기 N벌` 카드에서 이어서 할 수 있다.
4. **Given** 미분류 옷이 0벌, **When** 홈을 보면, **Then** 정리 대기 카드는 보이지 않는다.

### User Story 3 — 홈에서 오늘 입은 옷 바로 기록 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 옷이 있는 홈, **When** `오늘 입은 옷`에서 썸네일 2개를 누르고 `기록`을 누르면, **Then** 두 옷에 오늘 착용이
   기록되고 실행 취소 토스트가 뜬다.
2. **Given** 선택한 상태, **When** `날짜·메모`를 누르면, **Then** 기존 착용 기록 시트(오늘·어제·날짜 선택·메모)가 열린다.
3. 목록은 최근 입은 순, 같은 경우 많이 입은 순이며 입은 적 없는 옷은 최근 등록 순으로 뒤에 붙는다. 보관한 옷은 제외한다.

### User Story 4 — 속성으로 찾기와 이번 계절 (Priority: P2)

**Acceptance Scenarios**:

1. **Given** 옷장, **When** 상세 필터에서 색상 `검정`·`네이비`와 계절 `겨울`을 고르면, **Then** (검정 또는 네이비) 그리고 겨울인 옷만 보이고
   적용 전 결과 수가 보인다.
2. **Given** 11월, **When** `이번 계절` 칩을 켜면, **Then** 계절에 `가을`이 있거나 계절을 정하지 않은 옷이 보인다.
3. **Given** 검색어 `검정`, **When** 검색하면, **Then** 이름·브랜드·태그뿐 아니라 색상·세부 종류·소재·패턴 라벨이 `검정`을 포함하는 옷도 찾는다.

### User Story 5 — 색을 나눠 세탁 (Priority: P2)

**Acceptance Scenarios**:

1. **Given** 바구니에 흰 셔츠·검정 니트·청바지·실크 블라우스(손세탁), **When** 세탁 화면을 열면, **Then** `손세탁·드라이`, `데님`,
   `흰옷·밝은색`, `어두운색·색깔 옷`, `색상 미지정` 순서의 그룹으로 나뉘어 보인다(빈 그룹은 숨김).
2. **When** 그룹 헤더의 `그룹 선택`을 누르면, **Then** 그 그룹의 옷만 모두 선택되고 다시 누르면 해제된다.

### User Story 6 — iOS 사진 배경 제거와 사진 힌트 (Priority: P2)

**Acceptance Scenarios**:

1. **Given** iOS 17 이상, 설정 `사진 배경 자동 제거` 켜짐(기본), **When** 사진을 고르면, **Then** 배경을 지운 사진이 미리보기·옷장·상세에
   쓰이고 원본은 함께 보관된다. 색상 추출은 배경 제거본으로 한다.
2. **Given** 수정 화면, **When** `원본 사진 사용`을 누르면, **Then** 배경 제거본이 지워지고 원본이 쓰인다.
3. **Given** iOS 17 미만 또는 Android, **Then** 배경 제거 설정은 보이지 않고 원본만 쓴다.
4. **Given** iOS, 종류를 아직 고르지 않은 등록 화면, **When** 신발 사진을 고르면, **Then** 종류 `신발`(가능하면 세부 종류 `운동화`)이 제안된다.
   제안 라벨은 신뢰도 0.6 이상이고 정해진 매핑에 있는 경우만 쓴다.

### User Story 7 — 기기 내 AI로 자세히 분석 (선택, Priority: P3)

**Acceptance Scenarios**:

1. **Given** Apple Intelligence가 켜진 iOS 27 기기, **When** 설정을 열면, **Then** `기기 내 AI로 자세히 분석`(기본 꺼짐)이 보인다.
   미지원 기기·OS·Android에서는 보이지 않는다.
2. **Given** 켜짐, **When** 사진을 고르면, **Then** 기기 내 모델이 종류·세부 종류·색상·소재·패턴·계절을 제안하고 비어 있는 축만 채운다.
   분석 중에는 진행 표시가 보이며, 실패·시간 초과(20초)면 조용히 기존 제안만 쓴다.
3. 어떤 경우에도 네트워크·서버 모델(Private Cloud Compute)을 쓰지 않는다.

### Edge Cases

- 분석 실패(손상 이미지·메모리 부족·채널 오류): 제안 없이 등록을 계속한다. 영문 로그만 남긴다.
- 종류를 바꾸면 그 종류에 속하지 않는 세부 종류는 지운다.
- 구 데이터·v1 백업: 새 필드는 빈 값(세부 종류 없음, 색상·계절 빈 목록, 배경 제거본 없음)으로 읽는다.
- 여러 장 등록 중 일부 실패: 성공한 옷은 남기고 실패 수를 안내한다.
- 배경 제거 결과가 비어 있음(피사체 없음): 원본만 쓴다.
- 같은 사진을 다시 고르기·사진 제거: 배경 제거본도 함께 바꾸거나 지운다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-501**: 옷은 선택 속성 **세부 종류**(종류에 종속, 단일), **색상**(최대 3, 대표 순), **계절**(봄·여름·가을·겨울 복수),
  **용도**(데일리·출근·외출·모임·격식·여행·운동·홈웨어 복수), **소재**(단일), **패턴**(단일)을 가진다. 값 목록은 data-model.md §2 카탈로그를 따른다.
- **FR-502**: 등록 시 이름이 비어 있으면 `{대표 색상} {세부 종류}`, 세부 종류가 없으면 `{대표 색상} {종류}`(미분류면 `옷`),
  색상이 없으면 `{세부 종류}`로 이름을 만든다. 모두 없으면 `이름 없는 옷`.
- **FR-503**: 이름 입력에서 카탈로그 키워드(세부 종류·색상·소재·패턴)를 찾아 **사용자가 손대지 않은 빈 축만** 제안으로 채운다.
- **FR-504**: 사진을 고르면 기기 안에서 대표 색상을 추출해 색상 축이 비어 있을 때 미리 선택한다.
- **FR-505**: 등록 화면에서 앨범 사진을 한 번에 최대 30장 골라 각 사진으로 미분류 옷을 만든다(색상·자동 이름·배경 제거 포함).
- **FR-506**: **정리하기** 화면은 지정한 옷(없으면 활성 미분류 옷 전체)을 하나씩 보여 주고 종류·세부 종류·색상·계절·용도를 칩으로 저장한다.
- **FR-507**: 홈 최상단 **오늘 입은 옷**은 활성 옷 최대 12벌을 FR-US3.3 순서로 보여 주고, 다중 선택 후 `기록`(오늘) 또는
  `날짜·메모`(기존 시트)로 착용을 일괄 기록한다(#39 일괄 기록·실행 취소 재사용).
- **FR-508**: 홈은 활성 미분류 옷이 1벌 이상이면 **정리 대기 N벌** 카드를 보여 주고, 누르면 정리하기를 연다.
- **FR-509**: 옷장 **상세 필터** 시트는 세부 종류·색상·계절·용도 축을 제공하고 같은 축 OR·다른 축 AND로 결합하며 적용 전 결과 수를 보여 준다.
- **FR-510**: 옷장 **이번 계절** 칩은 현재 월의 계절(3~5 봄, 6~8 여름, 9~11 가을, 12~2 겨울)을 포함하거나 계절이 비어 있는 옷을 남긴다.
- **FR-511**: 검색어는 이름·브랜드·태그에 더해 세부 종류·색상·소재·패턴·계절 라벨과도 비교한다.
- **FR-512**: 세탁 바구니는 세탁 그룹(손세탁·드라이 > 데님 > 흰옷·밝은색 > 어두운색·색깔 옷 > 색상 미지정)으로 나눠 보여 주고
  그룹 단위 선택을 제공한다. 그룹은 관리 방법·세부 종류·대표 색상으로 계산하며 저장하지 않는다.
- **FR-513**: iOS 17 이상에서 설정 `사진 배경 자동 제거`(기본 켜짐)가 켜져 있으면 사진의 배경 제거본을 원본과 별도로 저장하고 표시에 우선 사용한다.
  수정 화면에서 배경 제거본만 지울 수 있다. 백업·복원은 배경 제거본을 포함한다.
- **FR-514**: iOS에서 사진 분류 라벨 중 data-model.md §3 매핑에 있고 신뢰도 0.6 이상인 라벨만 종류·세부 종류 제안에 쓴다.
- **FR-515**: Apple Intelligence가 사용 가능한 iOS 27 이상에서만 설정 `기기 내 AI로 자세히 분석`(기본 꺼짐)을 노출한다.
  켜면 사진을 기기 내 모델에 넣어 카탈로그 코드로 제한된 구조화 응답을 받고, 비어 있는 축만 제안한다. 20초 안에 끝나지 않으면 버린다(맥 실측 첫 호출 15.4초, 진입 시 prewarm).
- **FR-516**: 모든 분석은 기기 안에서만 수행한다. 네트워크·서버 모델·외부 분석 SDK를 쓰지 않는다(헌법 III).
- **FR-517**: 제안은 사용자가 확인·수정할 수 있는 선택 상태로만 표시하고, 저장 시 화면에 보이는 값만 저장한다.

### Key Entities

- **Item** 추가 필드: `subType`, `colors`, `seasons`, `material`, `pattern`, `cutoutPath` (data-model.md §1).
- **UserPreferences** 추가 필드: `removeBackground`(기본 true), `onDeviceAi`(기본 false).
- **AttributeSuggestion**(저장 안 함): 축별 제안 값과 출처(이름 키워드·색상 추출·사진 분류·기기 내 AI).

## Success Criteria *(mandatory)*

- **SC-501**: 사진 10장을 여러 장 등록 + 정리하기로 분류할 때 키보드 입력 0회로 끝낼 수 있다(위젯 테스트로 흐름 확인).
- **SC-502**: 제품 사진(단색 배경)에서 대표 색상이 사람 판단과 일치하는 비율 80% 이상(고정 이미지 단위 테스트 + 수동 표본).
- **SC-503**: 홈에서 옷 3벌 착용 기록이 탭 4회(3벌 선택 + 기록)로 끝난다.
- **SC-504**: 분석 실패·미지원 환경에서도 등록·정리하기가 같은 탭 수로 끝난다(분석 fake 실패 테스트).
- **SC-505**: v1 백업 복원·구 저장소 데이터가 새 필드 기본값으로 읽힌다(회귀 테스트).

## Out of Scope

- Android 온디바이스 AI(ML Kit GenAI·Gemini Nano·Subject Segmentation): 진단 데이터 전송이 헌법 III과 충돌한다. 사용자 결정에 따라
  "사용자가 켜는 실험 기능"으로 **별도 검토**한다(별도 spec, 헌법 예외 승인 필요).
- 앱 번들 ML 모델, 코디·캘린더, 로컬 알림 발송, 착용당 비용, 홈 위젯(제안서 P1-F·G, P2).
