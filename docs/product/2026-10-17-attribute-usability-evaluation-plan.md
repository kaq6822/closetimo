# 선택 속성(태그) 소규모 사용성 평가 계획 (#46)

**작성일**: 2026-10-17 **관련**: 이슈 #46, [제품·UX 검토 §3·§7](2026-10-14-product-ux-review.md), spec FR-005b~d, data-model.md §1.1c

> 이 문서는 **계획서**다. 평가는 아직 수행하지 않았으며 아래 수치는 목표안이다.
> 평가 전까지 태그는 **기본 접힘**으로 둔다(폼: "추가 정보 (선택)" 안, 옷장: 태그가 있을 때만 `태그` 칩 1개).

## 1. 결정해야 할 질문

1. 태그(선택 속성)가 **찾기 성공률과 시간**을 실제로 개선하는가?
2. 태그 입력이 등록 시간·이탈을 얼마나 늘리는가(입력 부담)?
3. 사용자가 실제로 반복해 쓰는 축은 무엇인가(색상·계절·장소·상황 등)? → 그 축을 **기본 노출**(폼 상단 칩, 옷장 필터 줄 상시 노출)할지 결정한다.
4. 비슷한 태그(예: 출근/회사/오피스)가 생기는가, 이름 변경·병합으로 정리할 수 있는가?

## 2. 참여자·기간

- 8~12명, 1~2주. 의류 수 적음/많음, 기록을 자주 잊는 사람, 운동·출근 의류를 함께 가진 사람, 큰 글자 사용자를 섞는다.
- 실제 기기에서 본인 옷 10~20점을 등록한다(전체 옷장 등록을 요구하지 않는다).
- 외부 분석 SDK는 쓰지 않는다. 동의한 관찰·화면 녹화·사용 일지·진행자 기록으로 측정한다(프로젝트 헌법 III).

## 3. 조건(피험자 내 비교, 순서 상쇄)

| 조건 | 설명 |
|---|---|
| A. 태그 없음 | 종류·용도·이름/브랜드 검색·입을 수 있음만 사용 |
| B. 태그 사용 | A + 태그 입력(폼)·태그 필터·태그 검색·일괄 태그 |

- 참여자 절반은 A→B, 나머지는 B→A 순서로 진행해 학습 효과를 줄인다.
- 각 조건의 찾기 과제는 서로 다른(난이도가 비슷한) 목표 옷을 쓴다.

## 4. 과제

| # | 과제 | 조건 |
|---|---|---|
| T1 | 옷 5점 등록(사진 포함). B에서는 "원하면 태그를 붙여도 된다"고만 안내 | A·B |
| T2 | "검정 상의 중 하나" 찾기(기억한 단서로 찾기) | A·B |
| T3 | "여름에 입을 하의 모두" 모으기(여러 결과) | A·B |
| T4 | 옷 6점을 다중 선택해 같은 태그를 한 번에 붙이고, 그중 2점에서 떼기 | B |
| T5 | 비슷한 두 태그(진행자가 미리 만든 "회사"/"출근")를 하나로 합치기 | B |
| T6 | 태그 하나를 삭제한 뒤 해당 옷과 착용 기록이 그대로 있는지 확인 | B |
| T7 | 평소처럼 착용 기록·세탁 바구니 이용(태그가 흐름을 방해하지 않는지) | A·B |

## 5. 성공 지표(목표안)

| 지표 | 측정 | 목표안 |
|---|---|---|
| 찾기 성공률 | T2·T3를 도움 없이 정답으로 끝낸 비율 | B ≥ A, B ≥ 90% |
| 찾기 시간 | 과제 시작~목표 옷 탭까지(녹화 기준) | B가 A보다 중앙값 20% 이상 짧음 |
| 입력 부담 | T1 옷 1점당 등록 시간, 태그 입력 시 추가 시간 | 태그 입력 추가 시간 1점당 10초 이하 |
| 자발적 사용 | 2주 동안 진행자 안내 없이 태그를 붙인 옷 비율·실제 태그 목록 | 관찰(목표 없음) |
| 일괄 편집 | T4 완료 시간·오류(잘못된 옷에 붙임) | 30초 이내, 오류 0 |
| 정리 | T5·T6 성공, "기록이 지워질까" 불안 언급 | 성공 100%, 불안 언급 0 |
| 흐름 방해 | T7에서 태그 때문에 생긴 지연·혼동 | 0건 |

## 6. 입력 부담 비교 방법

- 등록 시간은 "+ 탭"부터 "등록하기" 탭까지로 정의하고, B에서 "추가 정보 (선택)"을 펼친 경우와 아닌 경우를 나눠 기록한다.
- 태그를 입력한 옷과 아닌 옷의 등록 시간 차이를 참여자별로 구한 뒤 중앙값을 비교한다(소표본이므로 통계적 유의성은 주장하지 않는다).
- 사후 인터뷰: "태그를 붙이는 것이 귀찮았나(1~5)", "태그 덕분에 찾기 쉬웠나(1~5)", "어떤 단서로 옷을 기억하나".

## 7. 결정 규칙(평가 후)

- **기본 노출로 승격**: 찾기 시간·성공률이 B에서 뚜렷이 좋고(5절 목표 충족) 입력 부담 목표를 넘지 않으며, 참여자 과반이 같은 축(예: 계절)을 자발적으로 쓴 경우 → 그 축을 폼 상단·옷장 필터 줄에 상시 노출하거나 시스템 속성으로 옮기는 후속 이슈를 연다(ordinal enum 추가 시 마이그레이션 정의 필수).
- **현행 유지(접힘)**: 개선이 작거나 일부 사용자만 쓰는 경우.
- **축소**: 태그 때문에 등록·기록 빈도가 줄거나 혼동이 반복되면 태그 노출을 줄이고 기본 탐색·일괄 작업을 먼저 개선한다.

- [ ] 결과 정리 위치: `docs/product/` 아래 평가 결과 문서(작성 예정)

## 9. 한계

- 8~12명 소표본은 방향을 찾는 근거이며 대중 시장의 효과를 통계적으로 증명하지 않는다.
- 평가 전 현재 기본 노출(접힘)은 보수적 가정이며, 사용자가 태그 기능을 발견하지 못할 위험이 있다. 이 발견 가능성도 관찰 항목에 포함한다.
